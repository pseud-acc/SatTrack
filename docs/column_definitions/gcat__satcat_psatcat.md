# Column definitions: GCAT object and payload catalogs

Part of the SatTrack column definitions; see `00_overview.md` for the rules and decisions.

## Batch 1: GCAT object catalog (`satcat.tsv` → `stg__jsr__satcat`)

Source: GCAT "Object Catalog Column Descriptions", https://planet4589.org/space/gcat/web/cat/cols.html (GCAT release 1.8.8, data update 2026-10-24).

**Also applies to `satcat100k.tsv`** (GCAT "satcat100k (Extended)", objects with SATCAT number ≥ 100,000, same header), which feeds `stg__jsr__satcat100k`. Same doc blocks, with `_source_file` telling the two apart.

| # | GCAT col | Proposed name | Proposed definition (from source) | SatTrack note |
|---|---|---|---|---|
| 1 | JCAT | `jcat` *(existing)* | GCAT: "an alphanumeric identifier (JCAT...) to uniquely tag space objects": a catalog prefix letter plus a sequence number. From GCAT satcat `JCAT`. E.g. `S25544`, the ISS Zarya module. | **Detail:** GCAT's unique alphanumeric identifier for a space object: one prefix letter for the catalog it belongs to (A auxcat, C csocat, D deepcat, F ftocat, L lcat, R rcat, S standard, T tmpcat) followed by a 5- or 9-digit sequence number. S-catalog numbers match US SATCAT numbers one-to-one (S46112 = SATCAT 46112). PK. Test regex `^[A-Z]\d+$`. |
| 2 | Satcat | `satcat_ref` | GCAT: "For objects in the US Satcat, this field contains an integer value which is the US SATCAT number"; others hold a reason code. From GCAT satcat `Satcat`. E.g. `25544` (ISS Zarya); `NNA` (none assigned). | **Detail:** For objects in the US SATCAT, the integer US SATCAT number. One SATCAT number can cover several attached GCAT objects. Objects without a SATCAT entry hold a code giving the reason instead (e.g. `NNA` none assigned, `NNA A` remained attached, `NSO` suborbital). Text, because of the NNA/NSO codes. Not the same as Space-Track `satcat_id`. |
| 3 | Launch_Tag | `launch_tag` | GCAT: "an identifier for the launch. For orbital launches, this is the international (COSPAR) designation of the launch." From GCAT satcat `Launch_Tag`. E.g. `1998-067`, the ISS Zarya launch. | **Detail:** Identifier for the launch. For orbital launches, the international (COSPAR) designation of the launch. Otherwise a pseudo-COSPAR `yyyy-Xnnn` assigned by GCAT. It matches the launch tag in the GCAT launch lists and can be used to join objects to launches. |
| 4 | Piece | `cospar_id` *(existing)* | GCAT: "The piece designation for the object. For objects in the US SATCAT this is the COSPAR (International) designation." From GCAT satcat `Piece`. E.g. `1998-067A` (ISS Zarya). | **Detail:** Piece designation of the object. For objects in the US SATCAT, this is the COSPAR (international) designation, e.g. `2020-032A`. Its launch part usually, but not always, matches Launch_Tag. Join key to Space-Track `OBJECT_ID`. |
| 5 | Type | `sat_type` | GCAT: "At the coarsest level, we characterize the object as payload (P), rocket stage (R), component (C) or debris (D)." From GCAT satcat `Type`. E.g. `PPTH-MU` (ISS Zarya). | **Detail:** SatType string (see https://planet4589.org/space/gcat/web/intro/type.html). At the coarsest level: payload (P), rocket stage (R), component (C) or debris (D). First-letter accepted values P/R/C/D. **`Z…` (28 rows) → NULL** for the derived type (decided 2026-10-25). Raw stays in staging. |
| 6 | Name | `gcat_name` | GCAT: "My recommended name for the object. The name is based on that used by the owner/operator." From GCAT satcat `Name`. E.g. `Zarya`; `deb FY-1C` (debris from Fengyun-1C). | **Detail:** GCAT's recommended name for the object, based on the owner/operator's name. `X part` = an unidentified component that separated from X. `deb X` = debris from the breakup of X. Kept separate from Space-Track `object_name`. |
| 7 | PLName | `pre_launch_name` *(existing)* | GCAT: "an alternative name for the object. When available, it is the name used prior to launch by the manufacturer." From GCAT satcat `PLName`. E.g. `77KM  No. 175-01` (ISS Zarya). | **Detail:** Payload Name: an alternative name, usually the name used by the manufacturer before launch. On some debris it holds `RCS <n>` (radar cross-section in m², unreliable). `[UNID…` marks unidentified debris that may be assigned to the wrong launch. |
| 8 | LDate | `gcat_launch_date` | GCAT: "The launch date is given in UTC, with 1 day precision." From GCAT satcat `LDate` (a Vague Date). E.g. 1998-11-20 for the ISS Zarya module. | **Detail:** Launch date in UTC, to 1-day precision. More precise launch times are in the launch lists. Separate from Space-Track `launch_date`. |
| 9 | Parent | `parent_ref` | GCAT: "the 'parent object' which the object is attached to at the start of the phase, or the central body whose gravitational sphere the object is leaving." From GCAT satcat `Parent`. E.g. `S25545` (ISS Zarya). | **Detail:** At the start of the current phase, either the parent object the object is attached to (an Extended JCAT ID, sometimes with a port suffix) or the central body whose sphere of influence it is leaving. A trailing `*` warns that the Piece designation may not match the parent's launch. |
| 10 | SDate | `phase_start_date` | GCAT: "the start time for the current phase. In the simplest cases, it is the time when the object separated from its parent." From GCAT satcat `SDate`. Not carried into SatTrack's models. | **Detail:** Separation date (phase start date): the UTC start of the current phase, usually when the object separated from its parent. In GCAT's Vague Date format. Parsed with `gcat_date()` and a precision flag. |
| 11 | Primary | `central_body` | GCAT: "a string representing the central body for the current phase... (Usually, the central body is Earth.)" From GCAT satcat `Primary`. E.g. `Earth`, every value in the current data. | **Detail:** The central body for the current phase (usually Earth), named as in the GCAT Worlds file. |
| 12 | DDate | `phase_end_date` | GCAT: "the end time for the current phase. In the simplest cases, it is the time when the object reentered the atmosphere. If blank, the phase is still in progress." From GCAT satcat `DDate`. E.g. 1976-08-02. | **Detail:** Descent date (phase end date): the UTC end of the current phase, usually when the object re-entered the atmosphere. **Blank = the phase is still in progress.** In Vague Date format. |
| 13 | Status | `phase_status` | GCAT: "the event that ends the current phase." From GCAT satcat `Status`. E.g. `O` (in orbit), `R` (re-entered); `GRP` for the ISS Zarya module. | **Detail:** The event that ends the current phase. A phase status code (e.g. O in orbit, R re-entered, D deorbited, E exploded, L landed, DK docked). See https://planet4589.org/space/gcat/web/intro/phases.html. Accepted values from the phases page. **`R?` (13) and `L?` (2) → NULL in intermediate** (decided 2026-10-25: strict, not inferred). Raw stays in staging. |
| 14 | Dest | `phase_destination` | GCAT: "the destination of the current phase. This may be the reentry or landing location, the JCAT identifier for the new parent object... or the world name." From GCAT satcat `Dest`. E.g. `A06147` (ISS Zarya). | **Detail:** Destination at the end of the current phase: a re-entry or landing location, the JCAT of a new parent object, or the world whose sphere of influence the object is entering. Its meaning depends on Status. |
| 15 | Owner | `owner_code` *(existing)* | GCAT: "The OrgCode for the owner/operator of this object." From GCAT satcat `Owner`. E.g. `JSC` for the ISS Zarya module; `SPXS` (SpaceX) is the most common. | **Detail:** GCAT OrgCode of the object's owner/operator. May be composite (`A/B`) or uncertain (`?`). The `explode_org_codes()` macro splits these. |
| 16 | State | `state_code` *(existing)* | GCAT: "The OrgCode for the country/state associated with the owner/operator." From GCAT satcat `State`. E.g. `US` for the ISS Zarya module; `SU` for Soviet objects. | **Detail:** GCAT OrgCode of the country/state associated with the owner/operator. Feeds country resolution (D3). |
| 17 | Manufacturer | `manufacturer_code` *(existing)* | GCAT: "The OrgCode for the entity that built the object." From GCAT satcat `Manufacturer`. E.g. `KHRR` for the ISS Zarya module; `SPXS` (SpaceX) is the most common. | **Detail:** GCAT OrgCode of the entity that built the object. Composite/uncertain, as for owner. |
| 18 | Bus | `bus` | GCAT: "the spacecraft bus (chassis) type. It isn't standardized, and many objects are one-off." From GCAT satcat `Bus`. E.g. `77KS` (ISS Zarya); `Starlink V2MO`. | **Detail:** Spacecraft bus (chassis) type. Not standardised, and many are one-off. Most useful for commercial communications satellites, where one bus type is used by many owners. |
| 19 | Motor | `motor` | GCAT: "The name of the main thruster or rocket engine in the object's propulsion system." From GCAT satcat `Motor`; not standardised. E.g. `S400`, `11D428A`. | **Detail:** Name of the main thruster or rocket engine in the object's propulsion system, with particular attention to apogee motors. Not standardised. |
| 20 | Mass | `mass_kg` *(existing)* | GCAT: "Mass of this GCAT object in kg, at launch (meaning, at initial orbital insertion), not including mass of attached objects." From GCAT satcat `Mass`. E.g. 20,281 kg (ISS Zarya). | **Detail:** Mass of this GCAT object in kg at launch (initial orbital insertion), not including attached objects. |
| 21 | MassFlag | `mass_flag` | GCAT: "If the MassFlag is '?' then the value is an estimate, hopefully good to about 20 percent." From GCAT satcat `MassFlag`: `?` or blank. | **Detail:** `?` = the Mass value is an estimate, hopefully good to about 20%. Applies to all `*_flag` columns below: text in staging. Intermediate derives a `flag_*_estimated` boolean. |
| 22 | DryMass | `dry_mass_kg` *(existing)* | GCAT: "Dry mass of this GCAT object (which is a reasonable proxy for the mass of the object after its active lifetime). Value is in kg." From GCAT satcat `DryMass`. E.g. 19,000 kg (ISS Zarya). | **Detail:** Dry mass of this GCAT object in kg, a reasonable proxy for its mass after its active lifetime. Excludes attached objects. |
| 23 | DryFlag | `dry_mass_flag` | GCAT: "If the DryFlag is '?' then the value is an estimate, hopefully good to about 20 percent." From GCAT satcat `DryFlag`. E.g. `?` for the ISS Zarya module. | **Detail:** `?` = the DryMass value is an estimate (about 20%). |
| 24 | TotMass | `total_mass_kg` | GCAT: "Total mass of this object at launch (orbital insertion), in kg"; given on one of a set of attached objects, the others hold 0. From GCAT satcat `TotMass`. E.g. 20,351 kg (ISS Zarya). | **Detail:** Total mass at launch (orbital insertion) in kg of a set of attached GCAT objects. It's given on one of them (usually the S entry), and the others hold 0. The sum of the set's Mass values should equal TotMass. 0 means "carried on another object", not zero mass. |
| 25 | TotFlag | `total_mass_flag` | GCAT: "If the TotFlag is '?' then the value is an estimate, hopefully good to about 20 percent." From GCAT satcat `TotFlag`: `?` or blank. | **Detail:** `?` = the TotMass value is an estimate (about 20%). |
| 26 | Length | `length_m` *(existing)* | GCAT: "Longest dimension of the main body of the object in metres." From GCAT satcat `Length`. E.g. 12.6 m for the ISS Zarya module. | **Detail:** Longest dimension of the main body of the object, in metres. |
| 27 | LFlag | `length_flag` | GCAT: "If LFlag is '?' the value is a guess, hopefully good to about 20 percent." From GCAT satcat `LFlag`: `?` or blank. | **Detail:** `?` = the Length value is a guess (about 20%). |
| 28 | Diameter | `diameter_m` *(existing)* | GCAT: "the second longest dimension of the main body of the object in metres." From GCAT satcat `Diameter`. E.g. 4.2 m for the ISS Zarya module. | **Detail:** Second-longest dimension of the main body, in metres. Length × Diameter approximates the cross-section, not counting appendages. |
| 29 | DFlag | `diameter_flag` | GCAT: "If DFlag is '?' the value is a guess, hopefully good to about 20 percent." From GCAT satcat `DFlag`. E.g. `?` for the ISS Zarya module. | **Detail:** `?` = the Diameter value is a guess (about 20%). |
| 30 | Span | `span_m` *(existing)* | GCAT: "the largest dimension in metres of the entire object across all appendages (booms, solar arrays, antennae)." From GCAT satcat `Span`. E.g. 23.9 m for the ISS Zarya module. | **Detail:** Largest dimension of the whole object across all appendages (booms, solar arrays, antennae), in metres. |
| 31 | SpanFlag | `span_flag` | GCAT: "If SpanFlag is '?' the value is a guess, hopefully good to about 20 percent." From GCAT satcat `SpanFlag`: `?` or blank. | **Detail:** `?` = the Span value is a guess (about 20%). |
| 32 | Shape | `shape` *(existing)* | GCAT: "A string giving the approximate shape of the object." From GCAT satcat `Shape`. E.g. `Cyl + 2 Pan` (cylinder with two panels) for the ISS Zarya module; `Box + pan`. | **Detail:** Approximate shape of the object. Carried over from the old RAE table of Earth satellites. |
| 33 | ODate | `canonical_orbit_epoch` | GCAT: "Epoch of canonical orbital data", the orbit GCAT picks as "representative of the spacecraft's early operations." From GCAT satcat `ODate`. Not carried into SatTrack's models. | **Detail:** Epoch of the canonical orbit, in Vague Date format. The canonical orbit is the one GCAT picks as representative of the object's early operations, after initial positioning. Not the current orbit. Space-Track GP holds that. |
| 34 | Perigee | `canonical_perigee_km` | GCAT: "Conventional perigee height in km of canonical orbit. Equal to perigee radius minus equatorial radius of central body." From GCAT satcat `Perigee`. E.g. 393 km (ISS Zarya). | **Detail:** Conventional perigee height of the canonical orbit in km: perigee radius minus the central body's equatorial radius. Kept separate from GP `periapsis`. |
| 35 | PF | `canonical_perigee_flag` | GCAT: "If PF is equal to '?' the value is a guess." From GCAT satcat `PF`: `?` or blank. | **Detail:** `?` = the Perigee value is a guess. |
| 36 | Apogee | `canonical_apogee_km` | GCAT: "Conventional apogee height in km of canonical orbit. Equal to apogee radius minus equatorial radius of central body." From GCAT satcat `Apogee`. E.g. 399 km (ISS Zarya). | **Detail:** Conventional apogee height of the canonical orbit in km: apogee radius minus the central body's equatorial radius. |
| 37 | AF | `canonical_apogee_flag` | GCAT: "If AF is equal to '?' the value is a guess." From GCAT satcat `AF`: `?` or blank. | **Detail:** `?` = the Apogee value is a guess. |
| 38 | Inc | `canonical_inclination_deg` | GCAT: "Inclination of canonical orbit in degrees with respect to coordinate system equator." From GCAT satcat `Inc`. E.g. 51.59° for the ISS Zarya module; 53.16° for many Starlinks. | **Detail:** Inclination of the canonical orbit in degrees. Earth orbits are relative to the equator of date (TEME). Heliocentric orbits are relative to the J2000 ecliptic, and orbits around other bodies to that body's IAU equator. |
| 39 | IF | `canonical_inclination_flag` | GCAT: "If IF is equal to '?' the value is a guess." From GCAT satcat `IF`: `?` or blank. | **Detail:** `?` = the Inc value is a guess. |
| 40 | OpOrbit | `orbit_type_raw` *(existing)* | GCAT: "Orbit type of the canonical orbit." From GCAT satcat `OpOrbit`. E.g. `LLEO/I` ("Lower LEO/Intermediate": below 600 km, 25–85° inclination) for the ISS Zarya module; `LEO/S` ("Upper LEO/Sun-Sync"). | **Detail:** Orbit type of the canonical orbit. Values are listed in https://planet4589.org/space/gcat/web/intro/orbits.html. `orbit_regime` and `orbit_subtype` are split from it in intermediate. Those definitions come in a later batch from orbits.html. |
| 41 | OQUAL | `orbit_quality_note` | GCAT: "Source of the canonical orbit. Usually blank... 'J' means I estimated the orbit myself." From GCAT satcat `OQUAL`. E.g. `S`, `K`. | **Detail:** Orbit quality note: the source of the canonical orbit. Usually blank. `J` = estimated by McDowell himself. |
| 42 | AltNames | `alt_names` | GCAT: "A comma-delimited list of further alternative names for the object." From GCAT satcat `AltNames`. E.g. `ISS FGB:P` for the ISS Zarya module. | **Detail:** Comma-delimited list of further alternative names for the object. Intermediate may split it into a `VARCHAR[]`. |

## Batch 2: GCAT payload catalog (`psatcat.tsv` → `stg__jsr__psatcat`)

Source: GCAT "Payload Catalog Column Descriptions", https://planet4589.org/space/gcat/web/cat/pcols.html.

**Also applies to `psatcat100k.tsv`** (same header), which feeds `stg__jsr__psatcat100k`.

| # | GCAT col | Proposed name | Proposed definition (from source) | SatTrack note |
|---|---|---|---|---|
| 1 | JCAT | `jcat` | GCAT: "The JCAT identifier (letter followed by digits) identifies the object and ties this catalog to the object catalogs." From GCAT psatcat `JCAT`. E.g. `S25544`, the ISS Zarya module. | **Detail:** (shared block, batch 1 #1) Ties this catalog to the object catalogs. PK. |
| 2 | Piece | `cospar_id` | GCAT: "the piece designation, usually the COSPAR 'international Designation'. It is the same as that given in the object catalog." From GCAT psatcat `Piece`. E.g. `1998-067A` (ISS Zarya). | **Detail:** (shared block, batch 1 #4) Repeated from the object catalog for convenience. |
| 3 | Name | `un_registry_name` | GCAT: "The name in the payload catalog is the name given in the UN satellite registry, where available." From GCAT psatcat `Name`. E.g. `Zarya Cargo Block` for the ISS Zarya module. | **Detail:** Name given in the UN satellite registry, where available. Otherwise GCAT fills in another name for readability. `[Name]` in square brackets = registered, but no name given in the registration. GCAT advises preferring the object catalog name. |
| 4 | LDate | `gcat_launch_date` | GCAT: "Same as in object catalog, provided for convenience and cross checking": the launch date in UTC. From GCAT psatcat `LDate`. E.g. 1998-11-20 for the ISS Zarya module. | **Detail:** (shared block, batch 1 #8) Same as the object catalog. |
| 5 | TLast | `last_active_date` | GCAT: "The date on which the satellite was most recently known (by me) to be active." From GCAT psatcat `TLast` (a Vague Date). E.g. 2023-02-01 for the ISS Zarya module. | **Detail:** Last Known Active Time: the date the satellite was most recently known to GCAT to be active. GCAT updates it "infrequently and patchily", so an old date doesn't prove the satellite is inactive. `*` = no information. Vague Date format. D9. `*` becomes NULL. |
| 6 | TOp | `end_operation_date` | GCAT: "The date on which the satellite is believed to have completed regular operations." From GCAT psatcat `TOp` (a Vague Date); NULL while still operating. E.g. 1988-01-01. | **Detail:** End Operation Date: when the satellite is believed to have completed regular operations. After it, the satellite may still be used for tests or keep a beacon, but not for its primary purpose. This isn't the "end of primary mission", which can be much earlier. `*` = believed still operating. D9. `*` becomes NULL. |
| 7 | — (derived from TOp) | `flag_still_operating` *(existing)* | TRUE when GCAT says the payload is still operating (psatcat `TOp` is `*`, "believed to be still operating"); derived by SatTrack. E.g. TRUE for the ISS Zarya module. | **Detail:** TRUE when TOp is `*`, which GCAT documents as "the payload is believed to be still operating". Derived in intermediate (D9). |
| 8 | TDate | `end_transmission_date` *(existing)* | GCAT: "the date after which the satellite became completely silent and unresponsive, or when no further contact was made by its owners." From GCAT psatcat `TDate` (a Vague Date). E.g. 1988-01-01. | **Detail:** End of Transmission Date (GCAT's "Dead, Dead, Dead" date): after it, the satellite became completely silent and unresponsive, or its owners made no further contact. GCAT's preferred end-of-life date. `*` = believed still transmitting. D9. `*` becomes NULL. |
| 9 | — (derived from TDate) | `flag_still_transmitting` *(existing)* | TRUE when GCAT says the payload is still transmitting (psatcat `TDate` is `*`, "believed to be still transmitting"); derived by SatTrack. E.g. TRUE for the ISS Zarya module. | **Detail:** TRUE when TDate is `*`, which GCAT documents as "the payload is believed to be still transmitting". Derived in intermediate (D9). |
| 10 | TF | `end_of_life_flag` | GCAT: "End of life special flags." From GCAT psatcat `TF`. E.g. `Z` ("Zombie satellite: no longer controlled, but continues emitting a beacon signal"), `X` (end-of-life date is a guess). | **Detail:** End-of-life special flag: D = recovery capsule, a separate orbiting object for only seconds before the deorbit burn; E = deep-space mission, may be operating outside Earth orbit; U = thought still working, but the UCS active satellite list suggests not; X = end-of-life date is a guess and the satellite could still be partly operating; Z = zombie satellite, no longer controlled but still emitting a beacon. D9. Accepted values D, E, U, X, Z. |
| 11 | Program | `satellite_program` *(existing)* | GCAT: "This field identifies groups of related satellites." From GCAT psatcat `Program`. E.g. `TsM` for the ISS Zarya module; `Starlink 2MO S1`; `FY-1`. | **Detail:** Identifies groups of related satellites. GCAT uses it to organise its mission logs. |
| 12 | Plane | `constellation_plane` | The constellation plane or shell label GCAT gives the payload, as a short string: as observed, one or two numbers (e.g. `1 1`, `9 0`, `2`), sometimes with letters (e.g. `1 PA`, `X`). For example, STARLINK-38457 (NORAD 101256) has `10 1` and ONEWEB-0708 (NORAD 61613) has `1 1`. GCAT doesn't document the parts of the label. | Observed 2026-11-09: filled for 14,263 payloads in `fct__satellite_master` with 88 distinct labels, mostly Starlink (11,203), then OneWeb, Strela, Kuiper, Qianfan and others. Own value only (not inherited). |
| 13 | Att | `attitude_control` | GCAT: "The field describes the type of attitude control"; not yet systematically filled in. From GCAT psatcat `Att`. E.g. `P` ("Pointed, 3-axis stabilized"), `S` (spin stabilized). | **Detail:** Type of attitude control: G gravity gradient, P pointed/3-axis, PS Sun-pointed, PN/N nadir-pointed, S spin, U unstabilised, `-` unknown. GCAT says it "has not yet been systematically filled in". 2026-10-24 data: `-` 14,002; P 13,937; **D 1 → NULL** (undocumented). No completeness test. |
| 14 | Mvr | `maneuverability` *(existing)* | GCAT: "whether the satellite has or had a propulsion system capable of changing its orbit." From GCAT psatcat `Mvr`. E.g. `M` (manoeuvrable) for the ISS Zarya module; `D` (deorbit burn only). | **Detail:** Whether the satellite has or had propulsion able to change its orbit. M = maneuverable; D = can make a single deorbit burn. 2026-10-24 data: M 19,421; `-` 8,145; D 372; **N 2 → NULL in intermediate** (undocumented). Raw stays in staging. |
| 15 | Class | `ownership_class` *(existing)* | GCAT: "used to classify satellites as military, commercial, etc." From GCAT psatcat `Class`. E.g. `C` (civil) for the ISS Zarya module; `B` (business), `D` (defense), `A` (amateur/academic). | **Detail:** One- or (rarely) two-letter use class, usually based on the owner/operator's status: A amateur/academic/non-profit, B business (commercial), C civil (government, non-military), D defence (military, intelligence). Two letters = clearly shared dual use (e.g. BD). |
| 16 | Category | `mission_category` *(existing)* | GCAT: "It describes the general purpose of the satellite. A satellite may have one or two categories." From GCAT psatcat `Category`. E.g. `SS` (spaceship) for the ISS Zarya module; `COM` (communications). | **Detail:** General purpose of the satellite, independent of Class. One or two values joined by `/` (e.g. `IMG/TECH`). A trailing `?` = uncertain, and `*` = orbit data kept secret by the US government. Codes include COM, NAV, IMG, IMG-R, MET, SIG, TECH, SCI and AST (full list on the source page). Accepted values = the documented code list, after removing `?` and `*`. |
| 17 | Result | `mission_result` | GCAT: "a single letter used to identify satellites which failed early in their mission." From GCAT psatcat `Result`. E.g. `S` (success) for the ISS Zarya module; `F` (failed), `U` (unknown). | **Detail:** Flags satellites that failed early in their mission: S success, F failed, U unknown, N no test (e.g. the rocket failed before the satellite could operate). |
| 18 | Control | `control_centre` | GCAT: "Location of the spacecraft operations control center"; not filled in systematically. From GCAT psatcat `Control`. E.g. `TsUP`, `JSC`, `IKI`, the most common values. | **Detail:** Location of the spacecraft operations control centre. Not systematically filled in, but filled values should be reliable. |
| 19 | Discipline | `science_discipline` | GCAT: "For scientific satellites, this field may note one or more specific scientific areas in which the satellite is carrying out research." From GCAT psatcat `Discipline`. E.g. `PL` (planetary science), `ATM` (atmospheric science). | **Detail:** For scientific satellites, one or more research areas (e.g. ATM, ION, SOL, XRA; full list on the source page). Old `*` = major mission, which GCAT says to ignore. Strip `*`. **`GEO` (1 row, on an app object) → NULL** (undocumented; GCAT documents `GEOD`). |
| 20 | UNState | `un_state` *(existing)* | GCAT: "If the satellite is registered with the UN, this field contains the OrgCode string corresponding to the country which registered it." From GCAT psatcat `UNState`. E.g. `US` (ISS Zarya); `[US]` = unregistered. | **Detail:** OrgCode of the country that registered the satellite with the UN. `*` = differs from the owner country in the object catalog. `[XX]` = not registered, with the country GCAT thinks ought to have registered it. Blank = not registered and not considered to need it. Country resolution must handle `[…]` and `*`. |
| 21 | UNReg | `un_reg_doc` *(existing)* | GCAT: "the ID of the UN registration document in which the satellite was registered, if it was." From GCAT psatcat `UNReg`. E.g. `ST/SG/SER.E/614` for the ISS Zarya module. | **Detail:** ID of the UN registration document (usually ST/SG/SER.E or A/AC.105/INF series). `*` = listed online, but the document isn't yet available. Blank = not registered. |
| 22 | UNPeriod | `un_period_min` | GCAT: "the nodal period in minutes reported in the UN registration document, if any." From GCAT psatcat `UNPeriod`.
